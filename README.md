# Financial Planning & Scenario Modelling System

> **Decision problem:** How do operating assumptions translate into revenue, profit, cash generation, and downside/upside outcomes?

A reusable FP&A-style financial modelling system covering assumptions, forecasting, scenarios, sensitivities, and model quality assurance.

## Executive summary

The model is designed to make the relationship between operating assumptions and financial outcomes explicit rather than hiding the logic inside a black box.

## Core workflow

`Assumptions → Revenue → Costs → Profit → Cash generation → Scenarios → Sensitivities → Model QA → Decision readout`

## Analytical questions

1. Which operating assumptions drive the largest financial changes?
2. What happens under base, upside, and downside scenarios?
3. Where is the forecast most sensitive?
4. Which controls should be checked before decision use?

## Deliverables

- Assumptions input layer
- Revenue and cost forecast
- Three-statement-style model structure
- Scenario manager
- Sensitivity tables
- Model QA checklist
- Executive summary

## Sample outputs

The repository includes a reproducible illustrative scenario model generated by:

```bash
python src/generate_outputs.py
```

Outputs include:

- Annual forecast
- Scenario comparison
- Price/volume sensitivity grid
- Scenario profitability visuals
- Executive decision summary

## Data disclosure

All assumptions are synthetic and represent a fictional business. They are not market forecasts, investment research, or forecasts for a real company.

## Technical stack

Python · pandas · NumPy · Excel-compatible outputs · Plotly · financial modelling concepts

## Important limitations

- All assumptions are synthetic and illustrative.
- Scenario outputs are model responses to stated assumptions, not predictions of a real company.
- The model is not a substitute for audited financial statements, treasury forecasts, or investment research.
- Real-world deployment would require company-specific data, accounting policies, validation, and governance.

## Model governance

The project explicitly separates:

- inputs and assumptions
- calculation logic
- outputs
- scenario changes
- QA checks
- interpretation
